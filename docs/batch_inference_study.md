# 自己対戦におけるバッチ推論の効果検証

## 背景
自己対戦時のモンテカルロ木探索ではネットワーク推論が最も時間を要する処理であり、現状は 1 状態ずつシングル推論を行っている。推論をまとめて実行した場合の速度向上を確認するため、ベンチマークスクリプト `app/batch_inference_benchmark.py` を作成し、ランダムプレイで得た特徴量を用いた計測を行った。

## 計測条件
- 盤面サイズ 3×3、ネットワーク構成は既定値（`config/config.yaml`）
- ランダムな合法手を選択しながら収集した特徴量を 2048 個使用
- 各設定を 3 回ずつ実行して平均を算出
- コマンド: `python -m app.batch_inference_benchmark --samples 2048 --repeats 3 --batch-sizes 2 4 8 16 32 64`

## 結果
| 推論方式 | 平均秒数 | サンプル/秒 | シングル比 | 備考 |
| --- | --- | --- | --- | --- |
| シングル推論 | 4.245 s | 482.4 | 1.00× | 現行実装と同等 |
| バッチサイズ 2 | 4.441 s | 461.2 | 0.96× | オーバーヘッドでわずかに低速 |
| バッチサイズ 4 | 2.415 s | 847.9 | 1.76× | |
| バッチサイズ 8 | 1.118 s | 1831.3 | 3.80× | |
| バッチサイズ 16 | 0.619 s | 3310.9 | 6.86× | |
| バッチサイズ 32 | 0.299 s | 6853.7 | 14.21× | |
| バッチサイズ 64 | 0.166 s | 12308.1 | 25.51× | |

## 考察
- バッチサイズ 4 以上で明確な高速化が得られ、バッチサイズ 64 では約 25 倍のスループット向上となった。
- バッチサイズ 2 は PyTorch のオーバーヘッドが勝り、シングル推論よりも遅かった。
- 実際の自己対戦では探索木の分岐ごとに逐次的に推論しているため、そのままバッチ推論に置き換えるには探索手順の改修が必要である。ただし同時に複数の葉を展開する仕組みを導入できれば、大きな高速化が見込まれる。

## 今後の検討事項
- 探索アルゴリズムを拡張し、複数の葉ノードを一括で評価できるようにする。
- GPU 環境での性能も計測し、CPU 実行時との比較を行う。
- 実際の自己対戦ループにバッチ推論を組み込んだ際の収束性や勝率への影響を確認する。
